Análisis automáticos disponibles

El Dashboard Analytics de CL Tiene Soluciones es una plataforma web full-stack que extrae diariamente los registros de llamadas del SQL Server de la CUN, los procesa mediante un pipeline de análisis de texto (V4) y los publica en un dashboard interactivo con filtros dinámicos, gráficas de rendimiento y siete módulos de análisis con IA generativa (GPT-4o-mini). El sistema permite a los supervisores identificar patrones operativos, evaluar la calidad de atención y tomar decisiones basadas en datos en tiempo real.

Módulo Transcripciones — Endpoints de Datos

Invariante crítico: todos los endpoints del módulo de Transcripciones que asignan un ID a una llamada deben usar exactamente el mismo WHERE: COALESCE(Transcripcion_V4, transcripcion) IS NOT NULL AND {filtros}. Cualquier divergencia causa que el ID #N del dropdown apunte a una llamada diferente en métricas, IA o historial.

EndpointArchivoRol
GET /api/transcripcion/llamadas llamadas.py Dropdown: opciones con ID global. Muestra FECHA · Resultado · Asesor · Teléfono
GET /api/transcripcion/llamada/{id} llamada.py Transcripción completa + info con resultado, asesor, teléfono (FLOAT64 → INT64 → STRING)
GET /api/transcripcion/metricas/{id} metricas.py Panel métrico: Resultado, Duración Real, Duración, Plan, Turnos (desde V4), Saludo, WhatsApp. Acepta FilterModel
GET /api/transcripcion/historial/{telefono} historial_telefono.py Todas las llamadas al número dado con IDs globales. Sin filtros de sidebar (muestra historial completo del cliente)
Patrón ROW_NUMBER — sincronización de IDs
# Todos los endpoints usan este mismo CTE base: WITH id_provisional AS ( SELECT ROW_NUMBER() OVER (ORDER BY Fecha ASC) AS id, * FROM `desarrollo-investigaciones.call_center.cltiene_llamadas_procesadas` WHERE COALESCE(Transcripcion_V4, transcripcion) IS NOT NULL AND {filtros.get_query()} -- MISMO filtro en los 3 endpoints ) SELECT * FROM id_provisional WHERE id = {id}
Historial de llamadas por teléfono — flujo
DisparadorCondición en FiltrosLateral.jsxResultado
Usuario escribe número esTelefono(inputValue) — regex /^\d{7,15}$/ Fetch a /historial/{numero}; oculta dropdown de llamadas
Selección en dropdown cuentaActual ≠ null (viene de info.telefono de la llamada seleccionada) Fetch automático a /historial/{telefono_de_llamada}
Clic en tarjeta del historial changeAgent(h.id) donde h.id es el ID global de BigQuery Carga esa transcripción en ChatVisor + métricas actualizadas

⚠️ Telefono se almacena como FLOAT64 en BigQuery (ej. 3017384481.0). La comparación requiere CAST(CAST(Telefono AS INT64) AS STRING) = '{tel}'.

Filtros del Dashboard

Todos los endpoints del backend aceptan FilterModel (Pydantic) como parámetros de query. Los filtros se combinan dinámicamente en una cláusula WHERE sobre BigQuery. El componente Select.jsx excluye su propio filtro al cargar opciones para que el cambio de valor siempre muestre todas las alternativas disponibles.
